3. COPY SANG VS CODE KHÁC CÓ CHẠY ĐƯỢC KHÔNG
======================================================================

Có, nếu đủ file, đúng đường dẫn và mở qua một web server tĩnh.

Cách dễ nhất:

  1. Giải nén Co_Chill_Web_Source_Gon.zip ra thư mục mới, ví dụ:
       E:\ThanhTQ\co-chill-web
     Không giải nén đè lên repo cũ.

  2. Mở đúng thư mục có README.md trong VS Code.
     ZIP có một thư mục gốc tên co-chill-web; tránh mở nhầm lớp ngoài.

  3. Mở Terminal trong VS Code. Chạy ở thư mục có README.md:

       python -m http.server 8769 --bind 127.0.0.1 --directory online-preview

     Nếu máy có Python Launcher nhưng không nhận lệnh python, dùng:

       py -m http.server 8769 --bind 127.0.0.1 --directory online-preview

  4. Mở trình duyệt:
       http://127.0.0.1:8769/

  5. Giữ terminal chạy khi đang dùng web. Ctrl+C để dừng.

Nếu muốn chạy ngay trong repo gốc:

  cd "E:\ThanhTQ\App cờ tướng\xiangqi-ai"
  python -m http.server 8769 --bind 127.0.0.1 --directory online-preview

Nếu Python chưa nằm trong PATH, máy hiện tại có runtime này:

  & "C:\Users\thanh\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe" -m http.server 8769 --bind 127.0.0.1 --directory online-preview

Đường dẫn runtime trên chỉ dành cho máy hiện tại; không mặc định máy
khác cũng có. Trên máy mới cần Python 3.10 trở lên hoặc một server tĩnh
tương đương. Không cần API key, SQLite, npm install hay dịch vụ trả phí.

Ở đây Python chỉ gửi file HTML/CSS/JS cho trình duyệt. Python không
tính toán ván cờ hoặc lưu dữ liệu học cho bản Site này.

Nếu cổng 8769 đang có chương trình khác, đổi sang 8770 và mở URL tương
ứng. Đừng kết thúc một tiến trình chưa biết là của ứng dụng nào.

Không nên dùng cách nhấp đúp index.html như cách chạy chính thức.
Địa chỉ file:// có môi trường lưu trữ khác và có thể khác hành vi HTTP.

Bạn sẽ có CÙNG CHỨC NĂNG, nhưng chưa chắc có CÙNG TIẾN ĐỘ:
  - Tiến độ nằm trong localStorage của trình duyệt, không nằm trong code.
  - https://...chatgpt.site và http://127.0.0.1:8769 là hai origin khác.
  - Đổi trình duyệt, tên miền hoặc cổng không tự chuyển dữ liệu sang.
  - Copy code không mang theo ván, nháp và lịch ôn của người dùng.
  - Xuất dữ liệu có sẵn để đọc; chưa có chức năng nhập phục hồi tự động.

6. CÁCH DỌN CHÍNH REPO GITHUB MÀ KHÔNG MẤT DỮ LIỆU
======================================================================

Đã làm trong lượt này:
  - Tạo gói nguồn gọn riêng, không ghi đè repo cũ.
  - Giữ đúng 10 file web đã phát hành, không viết lại code.
  - Giữ kiểm thử quan trọng và mã luật tham chiếu.
  - Tạo file hướng dẫn/bàn giao này.

Chưa làm:
  - Chưa xóa hoặc untrack tài liệu trong repo gốc.
  - Chưa đổi remote, đổi nhánh mặc định hoặc đổi quyền public GitHub.
  - Chưa push các thay đổi của lượt này.

Quy trình đề xuất khi bạn yêu cầu dọn repo chính:
  1. Kiểm tra git status, nhánh, remote và commit chưa push.
  2. Sao lưu tài liệu/câu trả lời và backend đầy đủ ra chỗ riêng.
  3. Tạo một nhánh mới từ trạng thái hiện tại, ví dụ codex/web-only.
  4. Chuẩn bị diff giữ cấu trúc gói gọn; liệt kê file bỏ khỏi Git và nơi
     lưu bản gốc. Bạn duyệt danh sách này trước bước xóa/untrack.
  5. Chạy test từ chính cấu trúc mới và chạy thử web.
  6. Commit việc dọn cấu trúc; push đúng nhánh khi bạn yêu cầu.
  7. Sau khi xem diff và chấp nhận mới merge/chuyển nhánh mặc định.

Commit xóa file sẽ làm nhánh hiện tại gọn, nhưng phiên bản file cũ vẫn
có trong lịch sử. Đây là hành vi bình thường và giúp khôi phục; không
rewrite history hoặc force push chỉ để làm cây thư mục trông gọn hơn.

Nếu tài liệu từng chứa secret, xóa ở commit mới không đủ xử lý secret
đã lộ. Không có thao tác xóa lịch sử secret nào được thực hiện ở đây.

7. COMMIT, PUSH VÀ DEPLOY KHÁC NHAU THẾ NÀO
======================================================================

SỬA FILE → COMMIT → PUSH → DEPLOY
             |        |        |
             |        |        + Đưa phiên bản ra URL cho người khác dùng
             |        + Đưa commit lên GitHub
             + Lưu mốc thay đổi trong Git trên máy

“Commit lên GitHub” thường được nói gộp; thực tế cần commit rồi push.
Commit thành công chưa có nghĩa GitHub đã nhận code.

Bạn tự làm được. AI cũng có thể kiểm tra thay đổi, chạy test, tạo commit
và push nếu bạn yêu cầu cụ thể và máy có quyền truy cập repository.
AI không cần đọc password/token từ bạn trong chat. Không đưa token vào
file code, lệnh remote hoặc nội dung commit.

Ví dụ khi đang ở REPO GIT CÓ SẴN và muốn commit phần web:

  git status
  git diff
  git add online-preview
  git diff --cached --stat
  git commit -m "Improve home page and learning flow"

Nếu thay cả test hoặc README, stage đúng những file đã sửa. Tránh
git add . khi chưa biết các file mới là gì, đặc biệt Word và dữ liệu học.

Trước khi push:

  git branch --show-current
  git remote -v

Repo hiện tại đang ở nhánh codex-full. Khi bạn xác nhận muốn push nhánh
này lên remote hiện tại, lệnh tương ứng là:

  git push origin codex-full

Đừng dùng lệnh trên trong một thư mục khác chưa kiểm tra nhánh/remote.

Repo gốc hiện có remote:
  https://github.com/thanhtq2701-alt/xiangqi07.git

Lần kiểm tra local ngày 16/10/2026:
  HEAD: 0c9f20b
  Nhánh: codex-full
  So với ref origin/codex-full được lưu trên máy: ahead 3 commit.
  Chưa fetch trong lượt này, nên không khẳng định trạng thái remote mới
  nhất chỉ từ ref local đó. Ba commit local liên quan:
    261592a  Bản browser V4
    77f3fbe  Cập nhật UI UX và Luật
    0c9f20b  Báo cáo Site v3 và Word V5

Gói ZIP chưa có .git hoặc remote. Không git init rồi cố push đè vào repo
đang có lịch sử. Để chuyển chính repo hiện tại sang bản gọn, dùng quy

Quy trình đề xuất khi bạn yêu cầu dọn repo chính:
  1. Kiểm tra git status, nhánh, remote và commit chưa push.
  2. Sao lưu tài liệu/câu trả lời và backend đầy đủ ra chỗ riêng.
  3. Tạo một nhánh mới từ trạng thái hiện tại, ví dụ codex/web-only.
  4. Chuẩn bị diff giữ cấu trúc gói gọn; liệt kê file bỏ khỏi Git và nơi
     lưu bản gốc. Bạn duyệt danh sách này trước bước xóa/untrack.
  5. Chạy test từ chính cấu trúc mới và chạy thử web.
  6. Commit việc dọn cấu trúc; push đúng nhánh khi bạn yêu cầu.
  7. Sau khi xem diff và chấp nhận mới merge/chuyển nhánh mặc định.

Commit xóa file sẽ làm nhánh hiện tại gọn, nhưng phiên bản file cũ vẫn
có trong lịch sử. Đây là hành vi bình thường và giúp khôi phục; không
rewrite history hoặc force push chỉ để làm cây thư mục trông gọn hơn.

Nếu tài liệu từng chứa secret, xóa ở commit mới không đủ xử lý secret
đã lộ. Không có thao tác xóa lịch sử secret nào được thực hiện ở đây.

7. COMMIT, PUSH VÀ DEPLOY KHÁC NHAU THẾ NÀO
======================================================================

SỬA FILE → COMMIT → PUSH → DEPLOY
             |        |        |
             |        |        + Đưa phiên bản ra URL cho người khác dùng
             |        + Đưa commit lên GitHub
             + Lưu mốc thay đổi trong Git trên máy

“Commit lên GitHub” thường được nói gộp; thực tế cần commit rồi push.
Commit thành công chưa có nghĩa GitHub đã nhận code.

Bạn tự làm được. AI cũng có thể kiểm tra thay đổi, chạy test, tạo commit
và push nếu bạn yêu cầu cụ thể và máy có quyền truy cập repository.
AI không cần đọc password/token từ bạn trong chat. Không đưa token vào
file code, lệnh remote hoặc nội dung commit.

Ví dụ khi đang ở REPO GIT CÓ SẴN và muốn commit phần web:

  git status
  git diff
  git add online-preview
  git diff --cached --stat
  git commit -m "Improve home page and learning flow"

Nếu thay cả test hoặc README, stage đúng những file đã sửa. Tránh
git add . khi chưa biết các file mới là gì, đặc biệt Word và dữ liệu học.

Trước khi push:

  git branch --show-current
  git remote -v

Repo hiện tại đang ở nhánh codex-full. Khi bạn xác nhận muốn push nhánh
này lên remote hiện tại, lệnh tương ứng là:
